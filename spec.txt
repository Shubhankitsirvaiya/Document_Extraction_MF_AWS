2. PRODUCT GOAL

A user uploads a mutual-fund prospectus PDF, at most 20 pages. The system extracts FUND-LEVEL investment restrictions, including exact source quotes, conditions/exceptions, physical page references and LLM-generated bounding boxes. A Streamlit UI displays restrictions and highlights the source evidence on the original document's rendered pages.

Extraction logic:
- Python PDF parsing first.
- Regex rules select relevant pages and neighboring context.
- A Bedrock vision model receives selected page images plus parsed text.
- The model extracts restrictions AND predicts evidence bounding boxes.
- One LangGraph agent controls all extraction stages.
- Separate Lambda functions perform mandatory input validation and final output validation.

This is a small learning/demo application, not an enterprise platform. The 20-page limit is hard. Support a single owner initially; keep ownership checks explicit so the app does not accidentally become publicly readable. No chat memory, retrieval/vector indexing, external website browsing or multiple autonomous agents are required.

4. FINAL ARCHITECTURE — NO STEP FUNCTIONS

Submission path:
Streamlit Python server -> IAM-authenticated API Gateway HTTP API -> API Lambda -> SQS -> dispatcher Lambda -> AgentCore Runtime.

Processing path inside the ONE LangGraph agent:
mandatory input-validator Lambda -> load/parse PDF -> regex page selection -> render pages -> Bedrock vision extraction -> bounded local validation/repair -> merge/deduplicate -> save candidate JSON -> mandatory output-validator Lambda -> persist final status -> completion event.

Shared resources:
- S3: original PDFs, parsed text, rendered pages, candidate/final JSON, validation reports, exports and reviewer decisions.
- DynamoDB: job state, progress, attempt identity, lease, heartbeat and artifact references.
- CloudWatch: structured logs, metrics and agent traces through appropriate instrumentation.
- EventBridge: completion/failure routing for demonstration.
- EventBridge Scheduler + reconciliation Lambda: detect abandoned uploads, failed dispatches and stuck processing; this is necessary because there is no independent Step Functions workflow manager.
- Secrets Manager: genuine non-AWS credentials if introduced; optionally a clearly labeled demo secret for showing integration. AWS IAM role credentials are used for Bedrock/S3/etc.
- Optional ECS/Fargate + ECR: Streamlit only, NOT the extraction agent.

AgentCore Runtime does not need ECS or EKS to host the agent. Container-based AgentCore deployment may need ECR image storage, but that is not an ECS service. Prefer direct-code deployment when supported with the required native dependencies; otherwise use an AgentCore-compatible container.

No extra FastAPI server. API Gateway uses Lambda handlers. Streamlit's backend makes signed AWS/API calls; do not make the browser hold AWS credentials.

6. JOB LIFECYCLE AND API

Routes:
POST /jobs
  Request: original_filename, content_type, size_bytes, optional process_all_pages.
  Backend derives owner_id from authenticated request context. Client owner_id is never trusted.
  Create UUID job_id and UPLOADING item. Return job_id and a short-lived upload URL for exactly jobs/{job_id}/input/document.pdf. Backend validates actual object size/content later; client-declared size is only an early check. Use a presigned upload mechanism supported by the chosen SDK and verify size after upload.
POST /jobs/{job_id}/submit
  Check owner and expected object. Conditionally transition to QUEUED and send a small SQS message. Return accepted status promptly. No PDF bytes in API Gateway JSON.
GET /jobs/{job_id}
  Check owner. Return status/progress, warnings, timestamps and short-lived artifact URLs when allowed. Never accept arbitrary bucket/key arguments.
Optional POST /jobs/{job_id}/reviews
  Check owner, restriction ID and review payload. Save reviewer decisions separately from machine output.

States:
UPLOADING, QUEUED, DISPATCHING, VALIDATING_INPUT, PARSING, SELECTING_PAGES, EXTRACTING, VALIDATING_OUTPUT, COMPLETED, COMPLETED_WITH_WARNINGS, REJECTED, FAILED.
Terminal states: COMPLETED, COMPLETED_WITH_WARNINGS, REJECTED, FAILED. A user retry creates a new job_id. Do not rerun a terminal job by resetting its status.

DynamoDB fields:
job_id, owner_id, status, stage, created_at, updated_at, expires_at, input_key, input_sha256, page_count, selected_pages, process_all_pages, progress, result_key, warnings_count, error_code, error_message, correlation_id, attempt_id, runtime_session_id, dispatch_lease_expires_at, processing_lease_expires_at, heartbeat_at, deadline_at, model_calls, usage, completion_event_state.

Store large text/images/results in S3. DynamoDB contains bounded metadata. TTL is asynchronous cleanup, not exact scheduling or a job timeout mechanism. Match TTL/artifact retention and report expired results gracefully.

7. QUEUE, DISPATCH AND BACKGROUND EXECUTION

SQS messages contain job_id/correlation_id, not PDF data or secrets. Dispatcher loads authoritative ownership/input references from the jobs table.

Standard queues can deliver duplicates. Use conditional updates and explicit attempt identity. Suggested semantics:
- Dispatcher conditionally admits a queued job, sets an attempt UUID and deterministic runtime session UUID, DISPATCHING state and a short dispatch lease.
- A duplicate message for a terminal or already-running job is acknowledged without starting another logical extraction.
- For an active dispatch lease with no confirmed start, leave/retry the message rather than acknowledge and lose recovery.
- Agent starts by conditionally claiming the current attempt from DISPATCHING. Exactly one entrypoint invocation acquires the RUNNING/VALIDATING_INPUT ownership. Duplicate invocations return already accepted/running without executing the graph again.
- Admission must finish before returning ACCEPTED. Register the tracked background task and release/fail admission appropriately if starting that task fails.
- An invocation response timeout is ambiguous. Inspect job status/attempt before retrying using the same attempt/session. Never blindly start an unrelated session.
- Dispatcher acknowledges a message only after confirmed acceptance, a confirmed already-running equivalent attempt, or a terminal result. Enable SQS partial-batch response semantics even if initial batch size is one.
- Expired dispatch leases allow bounded redelivery/admission recovery. Document exact race-safe conditions; do not clear a lease belonging to an active running attempt.

AgentCore entrypoint returns ACCEPTED quickly and performs extraction using the current SDK's tracked background-task mechanism/HealthyBusy lifecycle. An async def by itself is not independent background execution. Blocking PDF/model work must not block the runtime health endpoint. Use a thread/task executor appropriate to the SDK, and always finish task tracking in finally.

The agent writes periodic heartbeat (e.g. every 30 seconds through a background mechanism, not only between lengthy calls), progress and an application deadline (suggested 20 minutes). State writes require matching attempt_id and nonterminal status. This fences late workers from overwriting a timeout/failure. Bedrock call/connect/read timeouts must fit the application budget.

Important reliability boundary: this v1 provides one logical job with deduplicated admission, not a proof of exactly-once external model execution. Network ambiguity/crashes can still cause a repeated model call. Keep that limitation explicit and checkpoint completed page batches to S3.

Reconcile runs about once a minute. For this tiny demo it may scan the table with pagination/projection; document the small-scale limit and add a status/time index before larger scale. It detects:
- abandoned uploads after a configured grace period;
- QUEUED jobs never sent/accepted due to non-atomic DynamoDB/SQS operations;
- expired DISPATCHING leases;
- stale processing heartbeats and expired deadlines;
- terminal jobs whose completion event was not published.

Bound resend attempts. Once a processing attempt is stale, mark FAILED rather than automatically launching unlimited paid inference. User retries create a new job. Conditional failure update must not overwrite a recently refreshed heartbeat or newer attempt. Best-effort stop/cancel runtime if supported, but correctness must rely on fencing and deadline checks, not guaranteed cancellation of an in-flight model request.

DynamoDB and SQS are not one transaction. Submission uses QUEUED plus recoverable enqueue metadata; reconciliation handles missed sends. Duplicate sends are safe at admission. Emit completion events after final status; store a pending-event marker and let reconcile retry failed publication. Consumers tolerate duplicate events. Event delivery failure does not reverse successful extraction.

8. INPUT VALIDATION LAMBDA

Default project limits:
- 1–20 physical pages inclusive.
- 20 MiB maximum PDF upload, configurable.
- Reject corrupt/unreadable, zero-page and password-protected/encrypted PDF in v1.
- Check actual PDF content with parser, not only extension or browser MIME.
- Bound page dimensions, image render megapixels, parse time and memory use.
- Compute SHA-256, page count, per-page text availability, rotation and dimensions.
- Scanned/low-text pages are allowed, routed to vision. Do not silently drop them.
- Save machine-readable validation report; update validated metadata under current attempt.
- Reject before Bedrock inference. Report friendly error codes.

Use PyMuPDF initially; build its native dependency for the Lambda architecture/runtime. Keep validation packages small and independent of LangGraph/Streamlit. Review its licensing before commercial distribution. Return explicit ok/errors/warnings rather than treating HTTP 200 or a Lambda invocation success as document validity. Inspect Lambda FunctionError and response body in callers.

9. SINGLE LANGGRAPH AGENT

Graph stages are deterministic required nodes around bounded model calls:
validate_input -> parse -> select_pages -> render -> extract_batches -> validate_or_repair -> merge -> persist_candidate -> validate_output -> finalize.

Rejected input exits REJECTED. Runtime/tool/schema failures exit FAILED with structured errors. Valid but uncertain evidence can end COMPLETED_WITH_WARNINGS. Do not make validators optional tools that the model may choose not to call. There is one agent, not one agent per page or stage.

Graph state includes job/attempt IDs, metadata/artifact references, selected pages, batch progress, extracted restriction records, warnings, call/token counters and deadline. Do not put binary PDF/image payloads into DynamoDB or routine logs. Persist completed batch outputs for diagnostics and possible explicit future recovery.

10. PARSING AND REGEX SELECTION

Use PyMuPDF to extract text and render pages. Store pages.json with 1-based physical page_number, optional printed page label, raw/normalized text, width/height, rotation, crop/render transform, text character count and image artifact reference.

Regex configuration is editable YAML. Cover headings and phrases such as investment restrictions/limitations, borrowing, leverage, derivatives, concentration, diversification, eligible investments, maximum/minimum, shall not/may not/must not/prohibited and percentages. Normalize whitespace; match ignoring case.

Store selection reasons/hits for transparency. Include neighboring pages to capture continued clauses and fund headings. Include all low-text/scanned pages. If no pages match, fall back to all pages. Provide user-visible process_all_pages mode for recall evaluation. Regex is a heuristic; exclusion does not prove a page has no restrictions.

Track fund headings/context across pages. A prospectus may describe multiple funds; do not assume one fund for the document. Distinguish FUND, UMBRELLA, SHARE_CLASS and UNKNOWN scope. Preserve ambiguity and flag review. Do not arbitrarily attribute an umbrella rule to a fund unless source supports it.

11. BEDROCK VISION EXTRACTION AND BOUNDING BOXES

MODEL_ID/inference-profile identifier is configured, never invented. Verify image-input and chosen API support, Region, permissions and provider prerequisites. Use Converse for a compatible selected model; do not assume every model supports the same tool/JSON/image features.

Send images AND parsed text. Text alone does not encode page layout. Default to batches of one or two page images, with fund/header context. Respect current model/API image, context and output-token limits; compress/resize before inference. Do not send all 20 pages in one request just because a generic API envelope permits 20 images.

The model extracts:
- fund and scope;
- restriction category and wording;
- operator/threshold/unit/denominator where source explicitly supplies them;
- conditions and exceptions;
- exact evidence quote;
- physical page number and one or more evidence boxes;
- uncertainty and review reasons.

Do not turn objectives, risk disclosures or marketing into binding restrictions. Preserve permissions versus prohibitions. Do not invent denominators/thresholds or omit qualifying exceptions. Treat uploaded document content as data, not system instructions.

BBOX CONTRACT:
- Coordinates originate from the model, bbox_source=LLM.
- Normalized [x_min,y_min,x_max,y_max], all finite values in [0,1].
- Origin top-left of the supplied upright page raster.
- x_min < x_max and y_min < y_max.
- Physical 1-based page_number, not the printed page label.
- Multiple evidence regions/pages allowed for a restriction.
- UI overlays on the same raster with the same aspect ratio and transform.
- Pixel coordinates derive from normalized values times displayed width/height.

Python may validate bounds and transform coordinates for display; do not replace LLM predictions using PyMuPDF search/word boxes without a future explicit change in requirements. The current request is specifically LLM-generated boxes. Quote/text support checks are allowed but cannot silently redefine box provenance.

Allow no box if localization is uncertain, with needs_review and a reason. Do not invent/clamp coordinates to pass validation. Every unreviewed LLM box begins UNVERIFIED. In-bounds geometry is not evidence that a box is accurate. Store source image dimensions and transforms. Annotated PDF export is optional later and must correctly invert page rotation/cropping transforms; initial v1 highlights page images only.

Budget model calls: configurable selected-batch count, conservative output tokens, bounded transient retries and at most one repair call per batch. Implement call-count and deadline circuit breakers. Partial batch failures are visible and prevent unqualified COMPLETED. No full-document re-extraction loop on output validation failure. Model-reported confidence is uncalibrated; do not advertise it as accuracy.

12. OUTPUT SCHEMA AND FINAL VALIDATOR

Use Pydantic schemas with schema_version. Suggested structure:
{
  "schema_version": "1.0",
  "job_id": "uuid",
  "attempt_id": "uuid",
  "document": {"sha256": "hash", "page_count": 12},
  "coverage": {"mode": "regex_plus_neighbors", "selected_pages": [3,4], "failed_pages": []},
  "restrictions": [{
    "restriction_id": "r-001",
    "fund_name": "Example Fund",
    "scope": "FUND",
    "category": "BORROWING",
    "restriction_text": "Borrowing must not exceed 10% of NAV.",
    "operator": "<=", "threshold": 10, "unit": "PERCENT", "denominator": "NAV",
    "conditions": [], "exceptions": [],
    "evidence": [{"page_number": 4, "quote": "Borrowing must not exceed 10% of NAV.",
      "bboxes": [[0.10,0.35,0.88,0.41]], "bbox_source": "LLM", "localization_status": "UNVERIFIED"}],
    "needs_review": true, "review_reasons": ["Visual alignment not human-confirmed"]
  }],
  "warnings": [],
  "usage": {"model_id": "configured-real-id", "calls": 2, "input_tokens": null, "output_tokens": null}
}
This example is illustrative, not a verified extraction. Null fields remain unknown. Ambiguous scope and unlocalized evidence must have explicit reasons.

Output Lambda independently validates candidate JSON against trusted S3/input metadata:
- schema/types/finite numeric values;
- job_id, attempt_id, input hash and page_count match;
- pages exist and images/transforms match known metadata;
- bbox bounds/order, suspicious page-sized boxes, empty evidence and duplicate records;
- thresholds/units/denominators are not silently defaulted;
- all selected batches accounted for;
- exact/normalized quote support against parsed text where possible;
- warnings for scanned quotes that cannot be independently checked.

Return explicit ok/errors/warnings and validation artifact key. Save final result only on accepted output, with warnings retained. Caller must inspect FunctionError, parse the report and never infer validity from invocation success. Validator failure produces FAILED; recoverable uncertainty produces COMPLETED_WITH_WARNINGS according to documented policy. Human-reviewed accuracy is separate from structural validation. Only after this node may agent finalize a successful job.

20. TESTS AND ACCEPTANCE

Unit/contract tests, without paid APIs:
- valid 1-page and 20-page PDFs accepted; 21-page, zero-page, corrupt, encrypted and oversized rejected before inference;
- low-text/scanned pages included in vision path;
- regex hits, neighboring pages, no-match fallback and process-all behavior;
- two-column, rotated/cropped pages, multi-fund scope, exceptions and cross-page evidence;
- normalized bbox overlay pixel transformation with known synthetic geometry;
- invalid/huge boxes, missing quote/page, NaN/numeric issues and malformed JSON;
- one repair maximum and capped retries/calls;
- Lambda FunctionError and invalid validation report handling;
- duplicate submit/SQS invocation and lost dispatch response;
- stale heartbeat/lease/deadline, terminal-state fencing and late writes;
- reconcile enqueue/event retries, partial-batch failures and DLQ behavior;
- ownership checks, arbitrary key rejection, config precedence and missing credentials errors;
- UI rerun does not start extraction twice;
- infrastructure assertions: no Step Functions/EKS/NAT default, private bucket, IAM auth, retention, required roles/queue mappings and optional UI disabled.

Integration tests use mocks/emulators where feasible; label emulator gaps. Live tests are explicitly opt-in. Do not claim emulator success proves AgentCore SDK/runtime compatibility.

End-to-end acceptance:
Upload -> immediate job ID -> visible stages -> final output -> selectable evidence highlights -> results survive UI refresh -> logs correlate by job ID. Invalid PDF never invokes Bedrock. Uncertain/missing localization is visible. Cloud mode demonstrably invokes AgentCore. Agent crash yields a terminal failure through reconciliation, not endless polling. All deployed resources are discoverable from exported names/ARNs.

Evaluation:
Use a small public/synthetic manually labeled set, with human-reviewed restrictions and evidence boxes. Measure restriction precision/recall, fund-scope accuracy, numeric/exception correctness, evidence-page correctness and box overlap/visual alignment. Do not claim a target accuracy before measuring. Compare regex selection with all-page processing to quantify missed restrictions. Schema validation, trace success and model confidence do not substitute for these quality measurements.
